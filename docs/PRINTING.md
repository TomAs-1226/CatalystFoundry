# Bambu print handoff

Foundry includes local Bambu Studio slicing. No separate Studio install or Bambu account is needed to slice. Printing uses the separately installed **Bambu Connect**, through Bambu's documented native file-import protocol. X1, X1 Carbon, X1E (with a reviewed external profile) and X2D can use this handoff. The included catalog adds exact X1 and X2D PLA/PETG mappings. Support in code and software fixture slicing do not establish live device acceptance.

1. Import real immutable CAD, or a real local STL with explicit units. Search by part name, ID, material or assembly/subsystem. Selecting a CAD subsystem reloads its exact occurrence counts; search alone preserves selection. Review classifications, quantities, orientation and placements.
2. In Slice setup, choose and review the exact bundled printer/material profile, apply it to the job, then slice. X2D retains both 0.4 mm nozzles in the upstream machine profile but exposes one selected filament and its primary-nozzle default. Multi-material/tool assignments are not exposed.
3. Open Project → Connect a printer at any time. The included companion setup downloads the pinned Windows installer linked from the [official Bambu Connect wiki](https://wiki.bambulab.com/en/software/bambu-connect), checks its SHA-256 and valid Bambu publisher signature, installs it per user and opens its empty login/pairing window. Existing publisher-verified installations are reused. Connect is a separate official app; its proprietary binary is not redistributed inside Foundry. No network plugin, credentials, team account or printer security setting is created by Foundry. The old download-site link returned 404 and has been replaced.
4. Under the successful slice, choose LAN-only or Bambu cloud. This records your intent; the official URL protocol cannot force a connection mode or target printer. Review the stated operator responsibilities and select **Open exact job in Bambu Connect**.
5. Inside Connect, select the actual X1/X2D and connection. Inspect the native toolpath, profile/nozzle/plate/material mapping and loaded filament, attest physical conditions, and explicitly press Print. LAN-only Connect does not require a Bambu account or internet; cloud operation uses Connect's own sign-in.

Opening Connect is recorded as **opened-for-review**, with printer status **unknown**. Foundry receives no printer acknowledgement through this protocol. It never marks the job printing or complete. Connect owns native preview, target selection, final dispatch and device status. No live printer or account was used to validate this implementation.

Companion setup is explicit; detecting installation never launches it or downloads software. Cloud passwords and pairing data are entered in Connect, and Foundry reports its login state as unknown. Team manufacturing records use Foundry's existing team workspace independently of the Bambu account. You can use an existing operator/team Bambu account inside Connect or choose LAN-only discovery; no shared credentials are baked into the app.

Native file handoff launches a publisher-verified Connect executable with the documented encoded file-import URL. The empty Open Connect action passes no file or printer commands. First application launch registers the protocol on Windows; successful installation alone is not treated as proof of login or printer pairing.

The trusted service requires a successful persisted worker result for the exact current manufacturing fingerprint, exact reviewed profile mapping, native 3MF hash and its matching single G-code plate/hash. It rejects fixture geometry, demonstration toolpaths, changed inputs and revoked matching toolpath mappings. It writes a content-addressed file and manifest in per-user `data/print-handoffs/`, and persists a receipt before opening the external handler. Repeated clicks or restarts do not reopen the same job/file implicitly, even if opening failed or was interrupted; inspect Connect or manually open the downloaded native file. A new exact slice/output creates a new handoff identity.

Unsupported proprietary Bambu commands still block Foundry's own approval. Native review handoff is a separate operation, with final operator checks in Connect. It does not create an approval, bypass fixture restrictions, qualify a machine/material or assert strength. Existing package export/assignment behavior remains distinct from printing.

Official references: [third-party integration protocol](https://wiki.bambulab.com/en/software/third-party-integration), [Connect](https://wiki.bambulab.com/en/software/bambu-connect), [LAN-only behavior](https://blog.bambulab.com/updates-and-third-party-integration-with-bambu-connect/).
