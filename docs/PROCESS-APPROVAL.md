# Process controls and native approval

This source update corrects native layer attachment and adds 261 process controls derived from the pinned Bambu Studio 2.8.2.61 source. Build, installation and native test outcomes belong in the delivered validation report; this document describes behavior.

1. Prepare imported or cached CAD, select the printer/nozzle/plate/filament and check the setup. Auto prepare chooses Adaptive Cubic for larger, lower-density meshes or Gyroid for smaller/dense meshes. At 100% density it uses Rectilinear. This is a geometry heuristic, not a load or strength calculation. Density and wall count remain yours. A manual native pattern overrides the suggestion.
2. Open Advanced Bambu settings, then All Bambu process settings. Search walls, top/bottom shells, infill, support interfaces, raft, brim, skirt, speed, acceleration or other process options. Native defaults come from the selected pinned profile. Reset removes an override. Machine profiles, filament recipes, custom scripts, per-object painting and multi-filament assignments are outside this editor.
3. Slice plate. The exact resolved process configuration is hashed into the job, and a supported result attaches before navigation to layers. Use Show layers to retry an interrupted attachment. Changing inputs while slicing prevents attachment. Withdrawing an existing mapping cannot silently restore it.
4. Inspect layers and the unchanged native 3MF, including printer start/end routines. Enter the reviewer, confirm the exact job and toolpath, and for a real unqualified setup explicitly confirm the printer/nozzle/plate/filament and native machine routines. This is a local operator attestation; printer/material tested flags stay false. Fixture CAD and marked demonstration G-code always remain non-manufacturable. Physical release still requires the existing separate operator checks.

Native previews require an exact single-plate 3MF whose embedded G-code matches the retained toolpath, independent archive and toolpath hashes, and uniquely ordered executable/start/end boundaries. Startup and shutdown remain in the native artifact and are not simulated. Print-region units, extrusion mode, movement parameters, conditional motion and supported dialect commands remain checked. Loose imported G-code retains the stricter complete-file parser; adding a Bambu comment cannot promote it.

Advanced settings use the native field names, types, enum values and ranges from the pinned source, serialized deterministically into the complete profile. Unknown fields, machine/filament selectors, paths and script injection are rejected. Changes require a new resolved profile and slice; approval binds the exact native artifact, CAD, placement, quantities and configuration. A setting that emits unsupported motion can still produce a native file for review, while Foundry approval remains blocked.

The library and slicer work locally from cached geometry; these operations make no Onshape requests. Restoring the latest slice requests matching metadata first, then only that result, instead of downloading every old native file into the renderer. No printer is contacted by slicing or approval. Live UI interaction, physical print quality and hardware compatibility require separate validation.

Historical limits and Linux results in SLICING.md predate this update. They are not Windows installation evidence. Browser UI automation remains disabled at the user's request.
