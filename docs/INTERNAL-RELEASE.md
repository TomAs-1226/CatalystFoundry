# Internal preview 0.2.4

Start with [Getting started](GETTING-STARTED.md) for installation, team parts, slicing, review and records. Download only the qualified Windows x64 Setup from the app repository's releases. Mac candidates have separate native/trust gates in [MACOS.md](MACOS.md).

This preview removes full engine verification from the workspace startup path and a potentially unbounded startup animation wait, shows the startup window promptly and verifies the complete bundled slicer with bounded streaming buffers. The workspace and saved project open while the complete engine verification runs in the background. Slicing routes and native execution wait for its successful result. A configured runtime is verified once during reopening and again before slicing. Verification still checks every inventoried byte; it is not skipped for speed. On the validation PC, an actual installed-candidate workspace appeared in 2.637 seconds on the first packaged full-runtime launch and 1.925 seconds on reopen, compared with the previously observed 130.211-second post-update launch. Cache state was uncontrolled, and these timings are not a guarantee on other laptops or proof that the old delay had a single cause.

Team reports and preferences persist in an account-scoped offline queue and retry after reconnect. Confirmed manufacturing state stays separate from pending delivery. The desktop polls its own record service every 10 seconds while connected and retries failures after 5 seconds; no Onshape geometry requests are used for this metadata. Server-side reservations still require internet and prevent overlapping copies. See [Record sync](RECORD-SYNC.md).

The native installer now refuses to proceed while Foundry processes are running, instead of closing them by executable name. This also protects isolated QA installations. Save and close Foundry before manually running Setup; use the app's saved restart for future OTA updates. A live native regression returned 1618 and left the isolated demo process running. An earlier isolated validation unexpectedly closed a normal session; that was the defect that prompted this guard. The saved local project remained present.

A real packaged-app workflow recording from 0.2.3 uses the public two-hole fixture, the bundled native engine, actual layer inspection and exact-job review. It deliberately displays the fixture's non-manufacturable guard. It does not demonstrate account login, printer acceptance or a physical print. Release validation retains raw PC reports locally and publishes a redacted summary.

The final normal Windows 0.2.4 installation opened its workspace in 2.115 seconds, preserved the saved project and retained the team connection and Onshape grant. Its build passed type checking and 430 tests (one platform skip); native NSIS save/reopen and all six installed-runtime fixture cases passed. An unchanged preference update completed the real durable-queue → Worker/D1 → confirmed-cache path. No production manufacturing report or printer action was used for that check. The public release includes both the 0.2.3 workflow recording and an actual 0.2.4 startup recording, labeled separately.

Apple Silicon and Intel 0.2.4 packages subsequently passed native hosted build, isolated installed save/reopen and six native fixture slices each. They are unsigned, unnotarized QA candidates with separate hashes and source identity. See [Mac results and remaining acceptance work](MACOS.md). Windows release assets remain unchanged.

Bambu Studio is bundled for offline slicing with pinned resources, its upstream license and corresponding source. Bambu Connect is installed separately through the official verified setup and keeps credentials/pairing in that application. Windows OTA uses signed Ed25519 manifests; the Setup executable remains unsigned with Authenticode. This preview is not physical printer/material qualification or a zero-defect guarantee.
