# Catalyst Foundry requirements audit

This audit traces the original product brief, the professional-design request and the guided-workflow/Windows request to implementation and tests. Source and test bodies were inspected, rather than treating a passing build or an earlier verification report as proof. Audit date: 2026-10-17 (user's Pacific date).

**Status definitions:** Implemented means a working local code path exists; it does not imply external-service qualification or physical validation. Partial means a useful subset exists with the gap stated. Deferred means unavailable by design or blocked on identified setup. The evidence column distinguishes real local execution, fixtures, injected API responses and external services. Final executed test commands and results belong in [GUIDED-VERIFICATION.md](GUIDED-VERIFICATION.md); test-file references here identify assertions, not a claim that an external system was used.

## Integration and release qualification

| Path | Qualification / setup boundary |
| --- | --- |

| Toolpath preview / approval / export | Actual text G-code is parsed/rendered; geometry and file bytes are hashed; approvals and package exports use real local domain code. Hand-authored demonstration G-code is visibly NON-MANUFACTURABLE and was not generated from selected CAD. |

| Windows installation | Corrected Electron/NSIS source and native build/install/two-launch verification scripts are supplied for the ROG agent. Windows, Wine, PowerShell and a desktop display are absent here; no installer EXE, native installation or launch is claimed. Linux bundle execution is a separate test. See [WINDOWS.md](WINDOWS.md) and [ROG_AGENT_HANDOFF.md](ROG_AGENT_HANDOFF.md). |

### Defects found and corrected during this audit

1. Windows confinement used POSIX `root + '/'`, which rejected valid Windows paths. The slicing owner changed this to portable relative-path confinement and added Windows/POSIX sibling-prefix, drive and traversal regressions.
2. The new intake setup text initially used an environment-variable name different from the backend. UI/server/docs now agree on `ONSHAPE_ACCESS_TOKEN_FILE`, raw UTF-8 token contents and external OAuth ownership.
3. The generated slice originally returned `slicerVersion: 'Bambu Studio 2.8.2.61'`, while the resolved manifest used `'2.8.2.61'`; the UI equality guard correctly rejected every result. The adapter now returns the exact pinned version and the HTTP integration test asserts equality before attachment. This fixed the contract without bypassing the guard.
4. The browser Onshape client initially stored unbound native `fetch` as a class property, which can raise an illegal-invocation error in a browser. The default is now explicitly bound to `globalThis`; an HTTP-adapter regression asserts the correct receiver. This browser-specific failure was not exposed by Node's more permissive fetch implementation.
