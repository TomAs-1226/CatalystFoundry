# Foundry visual system

Foundry uses the verified Catalyst desktop identity from CatalystApp, derived from Bezel and Detent. Mode: Operate. The audience prepares and reviews manufacturing jobs on Windows, often beside CAD and slicer tools.

The pinned world is charcoal ground, tonal surfaces, a single crimson signal, Segoe UI Variable text and Cascadia for hashes and measurements. Identity tokens are copied verbatim in src/catalyst-identity.css. Floating dialogs use glass; working panels use solid surfaces. Layout and responsive rules live in src/foundry.css.

Crimson belongs to controls and interface signals. Solid-part previews use the job's selected filament color, with neutral gray before selection; selection changes edges rather than replacing the object's color. This is an operator-selected spool preview, not printer telemetry. Repeated copies share oriented mesh/edge buffers, selection/color changes do not reparse plate meshes, pixel ratio is capped at 1.5, and static shadows update with scene content. GPU quality and low-end laptop frame rates remain manually untested.

The desktop centers a full-width 3D canvas. A 48 px header and 44 px workflow strip replace the rail and large project banner. Parts, part settings, print setup and checks open only when requested; the default workspace has no sidebars. Only one side panel opens at a time. Compact windows use drawers over the canvas. A small Project menu holds file operations, job records, integration help and revision review. Camera presets and the grid live under Camera options; Fit remains directly available. Detailed process settings and manual placement remain expandable. Source intake uses one compact column without the extra explanatory sidebar.

Controls retain readable labels, keyboard focus, error recovery, fixture/non-manufacturable markings and exact approval gates. No decorative live indicators or invented integration states. The user explicitly requested no Foundry computer-use automation; the latest layout is checked through source/type/unit/build checks, with manual visual review left to the user.

Advanced process controls remain inside the existing 320 px inspector. One search field and collapsed Quality, Strength, Speed, Support and Other groups expose the pinned Bambu process catalog without widening the normal canvas. Auto prepare explains its infill-pattern choice and preserves the chosen density, wall count and explicit overrides. Approval distinguishes demonstration geometry from an unqualified real setup; the latter has an explicit operator confirmation, with machine routine review and physical-release checks retained.

Review recovery belongs to the root app, independently of the 3D workspace panel. Slicing, completion, attachment and exact-result recovery continue across navigation. Review shows real running/attachment/error states and a direct retry or saved-slice recovery action. A current result is verified in job state before any successful layer preview is announced. The Project menu always exposes Connect a printer; Review and Export expose native handoff for a matching result. Cloud sign-in and LAN pairing remain in the official Connect app. Its setup is an optional pinned vendor download with hash and publisher validation, not an embedded login form or shared team password.

Confirmed direction: match CatalystApp, not Console/Pit. Charcoal/crimson tokens, Segoe UI Variable and Cascadia remain the shared identity. Legacy coral/green-tinted panels and DM Sans/Space Grotesk declarations have been removed. Buttons use the shared pill geometry and readable tinted crimson primary treatment. Assembly catalogs and native printing remain inside expandable panels; they do not shrink the default full-width 3D canvas. Latest appearance is source-audited and compiled only; the user prohibited Foundry UI automation.

Desktop source entry: Add robot remains visible in the header on every workflow page. Team parts shows the robot-link form directly, followed by the cloud catalog. Legacy project-file upload is excluded from this starting surface; local STL and fixtures remain under Advanced source options. Save progress retains the same local persistence operation. The 3D canvas layout and manufacturing gates are unchanged.


Plate workspace correction: direct View, Move, Rotate, Lay flat, On face, Drop and Auto prepare tools sit beside the canvas. Moving applies to the selected part and its copies. Manual rotation and picked-face choices are retained; unlocked source orientations use bounded mesh face/contact/height/overhang ranking in a worker. Settings open in a 320 px native popover, and the inspector overlays instead of resizing the canvas. The bottom bar stays compact. Toolpaths use instanced nominal beads with native width/height metadata, filament color by default, a separate support color, explicit layer markers and bounded XY arc tessellation. Travel starts hidden; machine setup/end motions stay outside the print display. Actual GPU and visual behavior remain untested under the user instruction.

Startup refinement: the user rejected the metal-pour illustration. The replacement is a quiet Foundry title, the small Catalyst mark and one 1400 ms crimson loading line. Local-engine/workspace stages remain real; no numerical progress is invented. Both native and React startup wait for finite animation completion, share the same source artwork/styles and avoid replay during handoff. Reduced motion is static with a 400 ms minimum. No video, filters, canvas or dependencies. The existing app is left open while the user tests functionality.

Preparation quality correction: the placement tools form a narrow vertical strip below the camera controls, with accessible names/tooltips and a separate visible Auto prepare button. Rotation expands beside the strip. The camera fit reserves the actual vertical strip width rather than pushing content below it. Neutral tone mapping, white studio lights, a matte plastic material and crease-aware normals replace tinted, overexposed faceted shading. Immutable source meshes and normals are cached with a 64 MiB cap; moving/recoloring a part does not repeatedly parse/smooth its STL. Native nozzle offsets align generated layer coordinates with the model. No source vertices are moved by the shading change.

Filament is directly available in the canvas header. Manual color works without a printer. A paired LAN status endpoint exposes only reported, present AMS slots; fresh matching printer/material colors can default a new neutral draft. Existing manual colors and generated jobs are not silently recolored. Pairing explicitly pins the printer certificate before sending the existing access code and stores it through the desktop encryption vault. Status refresh makes no print, motor or AMS-movement request. Cloud login and physical tray mapping remain inside Bambu Connect; cloud AMS telemetry is not implemented. Real printer/firmware acceptance and perceived visual quality remain untested.

Viewer performance correction: the legacy full-height rule now targets only the viewer, and the placement strip has an explicit 42 px width and content height. Auto prepare keeps its absolute position despite generic button styles. Mesh parsing, crease normals and feature edges run in one worker; moves and copies share immutable source and edge buffers with cached exact manufacturing matrices. Inactive mesh cache is capped at 64 MiB; active geometry stays valid. Pointer drags intersect the plate plane after one initial mesh pick, not every triangle on every move. Redraw requests coalesce into one animation frame and stop when idle. Interaction uses at most native resolution / 1 million pixels; rest restores up to 1.5 DPR / 2 million pixels. Toolpath beads reuse native endpoint/width/height arrays with six triangles per segment instead of twelve and no per-segment matrices. The nominal top and side faces retain the same native coordinates and width/height; manufacturing output is unaffected. A separate hidden synthetic WebGL fixture verifies shaders, actual pixels and draw counts; it does not operate Foundry. Actual app appearance, interaction FPS and low-end laptop performance remain manually untested.
